# RAG审核系统合规指南

本文档根据 RAG 审核助手（v1.1.0）知识库中 880 条真实审核记录反推整理。所有打回规律均来自实际审核意见，非推测。

## 审核系统基本信息

- 知识库总量：880 条（通过 499 / 一审打回 130 / 三审打回 246 / 废弃 5）
- 任务类型分布：L1 73.5% / L2 13.3% / 未知 13.1% / L3 0.1%
- 规范目标：L1 30% / L2 50% / L3 20%（实际 L2 严重不足）
- 附件格式：PDF 246 / Excel 26 / Word 9 / HTML 3 / 无附件 582 / 其他 14
- 审核模式：BM25 检索相似案例 + LLM 一次性结构化判定
- 核心理念：规范优先，大模型主判，历史案例仅供参考

## 判定标签

| 标签 | 含义 | 严重度 |
|------|------|--------|
| 通过 | 质量合格 | - |
| 一审打回 | 基础问题，需修改后重审 | 中 |
| 三审打回 | 隐蔽/严重问题 | 高 |
| 废弃 | 无法采用 | 致命 |

## 第一大雷区：题目中暴露附件内容（一审/三审打回）

### 具体表现

绝大多数打回记录都涉及这个问题。审核系统对此零容忍。

**典型打回意见：**
- "题目中过于明确附件的内容和用途，题目里不要直接告诉大模型用xx去做xx"
- "不要在题目中介绍附件，让模型自己看"
- "措辞可以修改为各个模块对于产物的要求是什么"

### 违规示例（会挂）

```
❌ "参照附件1《行业白皮书》，附件2《竞品分析报告》，你需要用附件3的财务数据计算ROI…"
❌ "附件A是去年的销售数据，附件B是今年的预算表，请对比分析…"
❌ "用Sheet1的用户数据做聚类，用Sheet2的标签做分类"
❌ "按照附件中的模板格式，完成以下分析…"
❌ "附件里有三份合同，请逐条审查…"
```

### 合规写法（会过）

```
✅ "我需要一份行业进入可行性报告，包含市场规模、竞品格局和财务测算三个模块"
✅ "手头有几份材料，你看看哪些能用，给我一个结论"
✅ "系统里有去年的销售数据和今年的预算，帮我对一下差异"
✅ "过去几个月的用户行为数据我整理了一下，你看看有什么规律"
✅ "合同在附件里，帮我审一下风险点"
```

### 核心原则

1. **题目描述「产物要求」，不描述「附件用途」**
2. **让模型自己发现附件里有什么、该用什么**
3. **不要出现"参照附件X""用附件Y""按照附件Z"等指引性措辞**
4. **如果说附件，说"我整理了材料""手头有数据"，不说"附件里有XX数据你用它做XX"**

## 第二大雷区：AI表述 / 模板化（一审打回）

### 具体表现

**典型打回意见：**
- "AI表述，模板化"
- "AI表述，戏太多"
- "描述需求，不要加戏"
- "修改一下表述，语言不够真实自然"
- "修改一下表达，使其更真实自然"
- "背景过于冗长，精简表达"

### 会被判定为AI表述的信号

1. **对称结构**：每个段落长度相近、句式工整对仗
2. **背景堆砌**：一段话里塞入过多无关事实（预算、价格、流程、证据清单），像案例简报而非同事描述问题
3. **过度标注**：每句话标注其功能（"这是我需要判断的""这个是附件里的"），不让事实自己说话
4. **叠问句式**：用分号或枚举逗号拼接 3 个以上独立问题——"我需要先判断几件事：窗口期还剩多少天、投诉书要写哪些内容、证据够不够…"
5. **顾问腔**：精细的角色介绍 + 工整的需求枚举 + 总结性收尾指令
6. **戏多**：过多情绪描写、心理活动、感叹，人为制造戏剧冲突
7. **啰嗦开场**：冗长的背景铺垫后才进入正题
8. **假装真人对话**：用"兄弟""帮我看看""你们一般怎么处理""麻烦你了"等招呼语假装对方是真人同事。出题人和模型都清楚这是AI交互，直接陈述工作任务即可。
9. **分段过多**：题目正文拆成5段以上，每段两三句话。真实工作请求是紧凑的，2-3段足够。

### 合规原则

1. **读出声来检查**：如果读起来像 PPT 大纲或会议纪要点，就是 AI 腔
2. **直接陈述，不加招呼**：跳过"兄弟""帮我看看"之类的假人对话，直接说"最近接了个项目，需要做X"
3. **紧凑不松散**：正文2-3段，不要拆碎。长段密集信息比短段分散信息更像真实工作请求
4. **事实自己说话**：不要标注每个事实的作用，让它们自然嵌入叙述
5. **结构可以略乱**：真实的同事求助不会分"背景-现状-需求-要求"四段
6. **节奏多变**：长句短句交错，不要整齐划一
7. **精简背景**：只说决策必需的信息，不是越多越好

## 第三大雷区：内部核心数据缺失（三审打回）

### 具体表现

当任务需要某个公司/机构/个人的具体内部数据才能完成，但题目未提供这些数据时，会被三审打回。

**典型打回意见：**
- "缺少该私募现有投资组合持仓等内部核心数据，无法完成定制化研究报告"
- "缺新赛道投资预算、矩阵评分权重"
- "缺内部运营明细、改革资源要求，方案偏泛化"
- "缺企业IT架构、预算、知识存量等数据，交付偏通用"
- "缺华东运营基准（单站成本、毛利）、可迁移资源内部数据等，精准度不足"
- "因缺少门店、仓配实时运营核心数据，无法完成可直接落地的保供限售安排"
- "缺本批样机参数、内部清机标准，仅能输出通用模板"
- "缺专属数据集、标注规则，无内部基准无法推进"

### 解决方法

两种选择：

**选项A：** 把缺失的内部数据做成附件提供（推荐）
**选项B：** 缩小任务范围，去掉依赖内部数据的部分
**选项C：** 将任务定位为"基于公开信息的初步分析"，明确标注信息缺口

## 第四大雷区：关键步骤数量不足（三审打回，仅L2）

### 规则

- **L1**：无明确步数要求，但推理链必须完整
- **L2**：推理步骤 ≥ 8 步（硬性要求）
- **L3**：更高要求（知识库中仅 1 条，极少使用）

**典型打回意见：**
- "L2要求推理步骤≥8步，现有仅7步，未达数量底线"
- "L2题型仅6步，未达≥8步要求，需补充"

### 注意

步数是硬门槛但非充分条件。步骤还必须：
- 每步有实质推理内容（非流水账）
- 不能把"阅读附件"拆成多步凑数
- 不能把行政性操作（"新建Excel""保存文件"）算作推理步骤

## 第五大雷区：模板化重复（一审打回）

### 具体表现

多个题目被标注"与唐思远_data_007模板化"，说明审核系统能检测跨题目的结构相似性。

**典型打回意见：**
- "与唐思远_data_007模板化"
- "有同类题目"

### 避免方法

1. **变化决策类型**：不要所有题都是"分析+建议"结构
2. **变化叙事角度**：第一人称、场景叙事、直接任务交替使用
3. **变化产物类型**：报告/方案/分析/诊断/规划/审查交替
4. **变化时间锚点**：不要都是"下周评审会前"

## 第六大雷区：附件与来源不匹配（三审打回）

### 具体表现

**典型打回意见：**
- "附件内容3与附件3链接不同"
- "数据皆于题目中体现，无附件、来源支持，真实性存疑"
- "合作数据呢"

### 规则

1. 附件内容必须与附件链接/文件一一对应
2. 题目中引用的数据必须有附件支撑，不能凭空出现
3. 如果题目说"我整理了数据"，附件就必须有对应的数据文件

## 第七大雷区：个人生活场景伪装工作场景（一审/三审打回）

### 具体表现

题目场景以个人/家庭生活决策为核心，但包装了职场元素试图蒙混过关。审核系统对此类问题会直接打回。

**典型打回意见：**
- "个人生活投资决策 不符白领工作场景"
- "个人生活决策，非专业工作场景"

### 核心判断标准

**决策的主要受益方是谁？**
- 提问者本人或家庭 → **个人生活场景，打回**
- 雇主、客户、专业组织 → **工作场景，继续**

### 违规示例（会挂）

```
❌ "HR让我在个税APP上选年终奖计税方式，单独还是合并" → 个人税务优化
❌ "同事推荐了几支基金，帮我分析一下" → 个人投资（除非是理财顾问服务客户）
❌ "公司有补充医疗方案让我选，帮我算算哪个划算" → 个人消费决策
❌ "孩子要上学了，比较学区房和私立学校的成本" → 个人生活规划
❌ "年底想换工作，帮我分析三个offer" → 个人职业决策
```

### 合规示例（会过）

```
✅ "客户让我帮他做年终奖税务筹划方案，他的收入情况如下…" → 税务顾问工作
✅ "公司要统一评估补充医疗保险供应商，这是三家方案…" → HR工作
✅ "帮客户做基金配置方案，这是客户的风险测评和资产情况…" → 理财顾问工作
✅ "员工对新个税政策有很多疑问，帮我做一个内部培训PPT…" → HR培训工作
```

### 直拒清单（出题前逐条检查）

以下场景主题直接拒绝，不试图"修复"：
- [ ] 个人税务优化（年终奖计税、个税筹划、专项附加扣除选择）
- [ ] 个人投资决策（基金/股票/理财产品选择）
- [ ] 个人住房决策（买房/租房/装修选择）
- [ ] 个人保险配置（重疾险/医疗险/车险选择）
- [ ] 个人医疗健康管理（体检方案/治疗方案/用药选择）
- [ ] 个人消费决策（购车/电子产品/大宗消费选择）
- [ ] 子女教育规划（学校选择/培训班选择/留学规划）
- [ ] 个人职业决策（offer选择/跳槽评估/职业转型）
- [ ] 家庭财务规划（储蓄/预算/债务管理）

### 修复策略

**不做"修复"——直接拒绝。** 给个人生活场景添加更多职场元素只会让伪装更拙劣，不会通过审核。正确的做法是：找到同一领域中真正的**专业服务工作场景**（专业人士为客户/雇主提供专业服务），从这个角度重新设计题目。



### L1（占比 73.5%，通过率最高）

- **特征**：单一专业领域的分析任务
- **典型场景**：数据分析、报表制作、风险评估、审查复核
- **推理链**：3-5 步关键推理
- **附件**：通常有 1-3 个附件，或明确的数据输入
- **产物**：单一格式（Excel/Word/报告）

### L2（占比 13.3%，打回率最高）

- **特征**：跨领域综合分析或深度研判
- **典型场景**：战略规划、行业深度调研、多维度决策分析
- **推理链**：≥ 8 步
- **附件**：通常 2-5 个附件，需跨文件交叉引用
- **产物**：通常包含多个模块

### L3（极少使用）

- **特征**：极高复杂度，多轮迭代
- 知识库仅有 1 条样本，当前不建议设计 L3 题目

## 出题自检清单

在提交前，逐一检查：

- [ ] 题目中没有"参照附件X""用附件Y""按照附件Z"等指引性措辞
- [ ] 题目中没有逐条介绍附件内容
- [ ] 题目场景是白领工作场景（非个人生活/投资/消费决策）
- [ ] 决策主要受益方是雇主/客户/专业组织（不是提问者本人或家庭）
- [ ] 没有"兄弟""帮我看看""你们一般怎么处理"等假装真人对话
- [ ] 题目正文2-3段，紧凑不松散
- [ ] 题目读起来像真实工作请求，不像 PPT 大纲
- [ ] 附件来源格式精简：附件编号+链接即可
- [ ] 背景信息精简，只说决策必需的
- [ ] 没有对称段落、叠问句式、顾问腔
- [ ] 所有引用的数据都有对应附件支撑
- [ ] 如果是企业/机构内部决策，所需内部数据已在附件中提供
- [ ] 题目结构不与已有题目雷同（变化决策类型、叙事角度、产物类型）
- [ ] 附件来源可追溯、可验证
